### A Modern Approach: Grafana + Loki/Prometheus

For total control over your dashboard and logs, you can build a highly customized, modern stack using Prometheus SNMP Exporter to poll devices and send metrics to Grafana. Send your Syslog streams to syslog-ng or rsyslog, which then format and push the logs to Grafana Loki. This allows you to view your syslog events right alongside your SNMP metrics in a single Grafana interface.

### Scanopy: A Network Mapping Tool

Scanopy is a network mapping tool that possesses SNMP discovery capabilities but lacks log-aggregation features. Its primary purpose is automated network diagramming and inventory mapping, rather than real-time event monitoring.

#### SNMP Capabilities

Scanopy utilizes active polling to enrich network documentation and map physical connections. It supports SNMPv2c polling for standard network hardware like switches, routers, and access points, and actively pulls interface tables (`ifTable`), system information, and LLDP/CDP neighbor data. However, as of mid-2026, SNMPv3 is not yet supported natively and remains on the roadmap.

#### Log-Aggregation Capabilities

Scanopy is completely missing centralized log management and cannot collect, ingest, or parse syslog streams or event logs from external servers and network infrastructure. While it can detect if log-aggregation services are running on target hosts, it does not aggregate logs.

### Comparison with Other Tools

LibreNMS, Observium, and Checkmk can auto-discover devices and trace physical connections, but they treat mapping as a background monitoring utility rather than a documentation tool. The differences between Scanopy's presentation-ready layouts and the "living data" maps generated by these full monitoring suites come down to core design philosophies.

* **LibreNMS & Observium**: Use dynamic force-directed physics engines to create maps that are often unreadable for large subnets.
* **Checkmk**: Relies heavily on parent-child relationships to create rigid dependency trees.

### Choosing the Right Tool

If your goal is to hand a polished PDF or SVG network diagram to a client or management team, stick with a tool like Scanopy. If you want a screen on the wall that blinks red the millisecond a cable gets pulled, deploy LibreNMS or Checkmk.

The following table summarizes the differences between Scanopy, LibreNMS, Observium, and Checkmk:

| Feature | Scanopy | LibreNMS / Observium | Checkmk |
| --- | --- | --- | --- |
| **Primary Goal** | Clean network documentation | Performance monitoring | Incident & alert management |
| **Layout Control** | High (Structured layouts, exportable to vector files) | Low (Automatic physics-based web rendering) | Medium (Dependency trees & parent/child maps) |
| **Link Information** | Port-to-port connections, inventory data | Real-time traffic, bits-per-second, link errors | Host status, service health, reachability paths |

Ultimately, the choice of tool depends on your specific needs and goals. By understanding the strengths and weaknesses of each tool, you can make an informed decision and choose the best solution for your network monitoring and mapping needs.
