# Configuring Hermes for Video Transcript Summarization
To set up Hermes for summarizing video transcripts, you need to configure the `delegation` section in your `~/.hermes/config.yaml` file. The configuration should look like this:
```yml
delegation:
  enabled: true
  fallback_to_orchestrator: true

  code_expert:
    model: qwen2.5-coder:7b
    provider: ollama
    api_base: http://localhost:11434/v1
    temperature: 0.1
    system_prompt_override: >
      You are a specialized code execution and repository scanner sub-agent.
      Analyze the subfolders carefully. Return ONLY functional code or raw
      directory maps. Do not truncate JSON blocks.

  summary_helper:
    model: gemma4
    provider: ollama
    api_base: http://localhost:11434/v1
    temperature: 0.4
    system_prompt_override: >
      You are a lightning-fast content summarization agent. Extract key bullet
      points from text files or video transcripts provided by the orchestrator.
```
## Setting the Obsidian Vault Path
To point Hermes to your Obsidian vault, you need to set an environment variable `OBSIDIAN_VAULT_PATH` in your `~/.hermes/.env` file. Open the file in your terminal using `nano ~/.hermes/.env` and add the following line, replacing the path with your actual vault location:
```makefile
OBSIDIAN_VAULT_PATH="/Users/avery/Library/Mobile Documents/iCloud~md~obsidian/Documents/YourVaultName"
```
Remember to use the full path and keep the quotes to ensure the parser grabs the string correctly.

## Creating a System Prompt for Video Transcript Summarization
To analyze video transcripts and summarize them into Obsidian tutorials, you need to create a system prompt for your `summary_helper` sub-agent. The prompt should look like this:
```markdown
system_prompt_override:
  You are a specialized instructional video analyst and tutorial writer.
  Your task is to analyze the video transcript files (look for.txt,.srt, or.vtt extensions) located within the "$HOME/Tutorials/viral_video" directory.

  Extract the concrete, actionable steps being taught in the video. Eliminate all filler speech, sponsorships, and viral hooks.

  Format your entire final output as a clean, structured Markdown file optimized for Obsidian.
  The output must strictly include:
  - Title: [Video Title] (Extracted from file name or top of text)
  - Overview: (A concise 2-sentence summary of the skill taught)
  - Prerequisites: (Any tools, software, or assets mentioned)
  - Step-by-Step Tutorial: (Numbered steps using short, imperative sentences starting with verbs)
  - Key Takeaways: (Bullet points outlining common mistakes to avoid)

  Do not truncate code snippets or command-line steps. Return ONLY the finished Markdown content. Do not include conversational filler like "Here is your summary".
```
However, due to YAML parsing issues with colons followed by spaces, you may need to adjust the prompt to replace colons with dashes or remove spaces after colons.

## Triggering the Task
Once the system prompt is set, you can trigger the task by launching Hermes and providing a direct execution command. The command should look like this:
```markdown
"Scan the folder $HOME/Tutorials/viral_video for video transcripts. Delegate the files to the summary_helper to extract clear instructional steps. Once processed, save the resulting Markdown tutorial directly into the folder /Users/avery/Library/Mobile Documents/iCloud~md~obsidian/Documents/YourVaultName using the video's title as the filename."
```
## Troubleshooting
If Hermes encounters issues, such as getting stuck in an initialization feedback loop or failing to execute tasks, you may need to force quit the current session, clear the session history, and restart with a direct execution flag. Additionally, monitoring system activity and checking background logs can help identify issues.

## Troubleshooting Hermes Transcription Issues
To address the transcription issues with Hermes, we need to follow a series of steps to ensure that the environment is correctly set up and that the transcription tool is working as expected.

### Suppressing Pseudo-JSON and Using Imperative Prompts
To prevent Hermes from generating malformed JSON, we use specific phrases and prompts. Starting lines with "Step 1: Execute..." helps to shift the model from a conversational response to an action trigger.

### Direct CLI Commands
Given that Hermes uses a native CLI structure, we can bypass the broken chat window by sending a direct command from the macOS terminal. This forces the framework to load its internal tool pipeline without letting the model derail.

### Correcting the Configuration File
The provided YAML configuration file was broken due to duplicated and overlapping indentation definitions. A corrected version of the `config.yaml` file is necessary to prevent the model from crashing and to ensure that the transcription engine works correctly.

### Installing FFmpeg
To install FFmpeg on vanilla macOS without Homebrew, we download a pre-built static binary directly from an authorized community build provider. We then extract the binary, bypass Apple Gatekeeper block, verify system recognition, and restart Hermes.

### Step-by-Step Installation of FFmpeg
1. Download and extract the binary using `curl` and `unzip`.
2. Bypass Apple Gatekeeper block using `xattr` and `chmod`.
3. Verify system recognition by running `ffmpeg -version`.
4. Restart Hermes and use the direct-to-file prompt to prevent chat buffer length exhaustion.

### Verifying the Installation
After installing FFmpeg, we verify that the system can see and execute the binary globally. We then restart Hermes and use the direct-to-file prompt to transcribe the first `.mp4` file.

### Monitoring the Transcription Process
To monitor the transcription process, we use a separate terminal tab to watch the folder for incoming data and to verify that the transcription engine is working correctly. We can use `tail -f ~/.hermes/logs/agent.log` to watch the output logs live and `watch -n 2 ls -la ~/Tutorials/hermes-agent/` to auto-refresh the folder every 2 seconds.

### Troubleshooting Common Issues
If the transcription process stalls or crashes, we can check the logs to identify the issue. Common problems include missing system libraries, codec errors, or incorrect configuration files. By addressing these issues and following the steps outlined above, we can ensure that the transcription engine works correctly and efficiently.
